二、兵马未动，粮草先行：获取 V2Ray 配置信息的必备功课

任何一场技术战役，前期的准备工作往往决定了最终的成败。在 Quantumult 中添加 V2Ray，我们首先需要拿到一份“通关密令”——也就是你的 V2Ray 服务配置信息。

通常情况下，这份配置会以 JSON 格式呈现，里面包含了你连接服务器所需的全部核心参数。如果你是从服务商那里购买的 V2Ray 服务，那么他们通常会在你的用户面板中提供一个二维码或者一个订阅链接，你只需要用浏览器打开或扫码，就能看到类似下面的结构：

json { "v": "2", "ps": "我的香港节点", "add": "hk.example.com", "port": "443", "id": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx", "aid": "64", "net": "ws", "type": "none", "host": "hk.example.com", "path": "/path", "tls": "tls" }

别被这堆字母数字吓到，你并不需要深入理解每一行的含义。你只需要像“寻宝”一样，从中提取出以下几个关键宝藏：

  • 服务器地址（add）：这是你的 V2Ray 服务器的域名或 IP。
  • 端口（port）：服务器监听的端口号，常见的有 443、80、8443 等。
  • 用户 ID（id）：一个 UUID 格式的字符串，相当于你的“身份证号”，用于服务器识别你的身份。
  • 额外 ID（aid）：通常是一个数字，用于混淆，默认为 0 或 64。
  • 加密方式（security）：虽然 V2Ray 的 VMess 协议自带加密，但这里通常指的是 TLS 或 none。
  • 传输协议（net）：如 TCP、WebSocket（ws）、HTTP/2 等。
  • 伪装类型（type）：如 none、http、srtp 等，用于伪装流量特征。
  • 伪装域名（host）：当传输协议为 WebSocket 或 HTTP/2 时，这个字段必不可少。
  • 路径（path）：WebSocket 连接时的路径，通常以 / 开头。

小贴士：如果你手头只有一条 vmess:// 开头的链接，别慌！你可以去网上搜索“vmess 链接解析工具”，将链接粘贴进去，就能轻松解码出上述所有参数。这就像拿到了一封加密信件，而解析工具就是那本密码本。

三、正式实操：在 Quantumult 中导入 V2Ray 配置的详细步骤

现在，我们已经手握所有“弹药”，是时候进入主战场了。请跟随我的节奏，一步一步完成配置。

第三步：打开 Quantumult，进入配置的主场

在你的 iOS 设备上找到那个蓝底白图的 Quantumult 图标，轻点打开。如果是第一次使用，你可能需要允许它添加 VPN 配置描述文件，这是 iOS 系统对网络代理工具的正常要求，选择“允许”即可。

进入主界面后，你会看到底部有几个标签页，比如“首页”、“规则”、“配置”和“设置”。我们需要点击右下角的“设置”图标，这个齿轮状的图标是进入所有高级选项的入口。

第四步：创建或编辑配置文件

在“设置”界面中，向下滑动，找到“配置文件”一栏。点击进入后，你会看到当前默认有一个名为 [default] 的配置文件。我们有两种选择：要么直接编辑这个默认文件，要么新建一个专属的 V2Ray 配置文件。为了避免混淆，我建议你新建一个。

点击右上角的“+”号，或者选择“新建”按钮，输入一个你喜欢的名称，比如“MyV2Ray”。创建完成后，点击这个文件名称，即可进入编辑模式。

注意：Quantumult 的配置文件是纯文本格式，支持多种语法。我们只需要在正确的位置添加 V2Ray 的服务器信息即可。

第五步：写入 V2Ray 服务器信息 —— 核心中的核心

在编辑界面中，你会看到一些示例文本。别管它们，我们直接在文件末尾或者合适的位置，按照 Quantumult 的语法规则，写入你的 V2Ray 服务器信息。

Quantumult 的 V2Ray 配置语法非常直观，通常采用以下格式：

[server] vmess://base64编码的配置信息

但为了更清晰，我们也可以使用明文格式。假设你的服务器信息如下：

  • 地址：hk.example.com
  • 端口：443
  • 用户 ID：xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
  • 额外 ID：64
  • 传输协议：ws
  • 伪装域名：hk.example.com
  • 路径：/path
  • TLS：开启

那么，你在配置文件中应该这样写：

[server] hk.example.com:443 = vmess, hk.example.com, 443, username=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx, ws=true, host=hk.example.com, path=/path, tls=true, aid=64

语法拆解：

  • hk.example.com:443：这是给这个服务器起的名字（可随意），冒号前是备注，冒号后是端口（这里端口可以省略，因为后面有）。
  • vmess：指定协议类型。
  • hk.example.com：服务器地址。
  • 443：服务器端口。
  • username=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx：你的用户 ID。
  • ws=true：启用 WebSocket 传输。
  • host=hk.example.com：WebSocket 的 Host 头。
  • path=/path：WebSocket 的路径。
  • tls=true：启用 TLS 加密。
  • aid=64：额外 ID。

如果你使用的是 TCP 传输，则不需要 ws、host、path 这些参数，只需保留 tls 和 aid 即可。例如：

[server] my-tcp-server = vmess, my.server.com, 443, username=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx, tls=true, aid=0

写完这些后，记得点击右上角的“保存”按钮。此时，你的 V2Ray 配置已经成功写入 Quantumult 的“大脑”了。

第六步：启用配置并测试连接

保存配置后，返回 Quantumult 的主界面。你会发现，在“配置”下拉菜单中，已经可以看到你刚刚创建的 MyV2Ray 文件了。选中它，让它成为当前生效的配置。

接下来，在首页界面，你会看到一个巨大的“启动”按钮（通常是一个开关或一个纸飞机图标）。轻轻滑动或点击它，Quantumult 会开始尝试连接你的 V2Ray 服务器。

此时，请留意状态栏的变化。如果一切顺利，你会看到状态变为“已连接”或类似提示，并且你的网络流量开始通过 V2Ray 隧道传输。

验证是否成功：最简单的测试方法，就是打开 Safari 浏览器，访问一个你平时无法访问的网站，比如 Google 或 YouTube。如果页面能流畅加载，恭喜你，你已经成功解锁了全球互联网！如果无法访问，请回到第二步，仔细检查你的配置参数是否填写正确，尤其是服务器地址、端口和用户 ID 这些关键信息。

四、进阶技巧：让 Quantumult 更懂你的网络需求

当你已经能够成功连接 V2Ray 后，你可能会发现 Quantumult 还有更多宝藏等待挖掘。比如，你可以利用它的规则系统，实现在不同网络环境下自动切换代理策略。

在“配置”文件中，你可以在 [filter_remote] 或 [filter_local] 部分添加规则。例如：

``` [filter_local]

直连国内网站

host-suffix, .cn, direct

代理国外网站

host-suffix, .google.com, proxy

其余所有流量走代理

final, proxy ```

这样，当你访问百度时，流量直接连接；而访问 Google 时，流量则走 V2Ray 代理。这种精细化的分流策略，不仅提高了访问速度，还大大节省了代理服务器的流量资源。

五、疑难杂症排查：遇到问题？别慌，这里有解药

在实际操作中，你可能会遇到一些“拦路虎”。别担心，我们为你准备了几个常见的“急救包”。

问题一：显示已连接，但无法访问外网？

这通常意味着你的 V2Ray 服务器本身没有问题，但可能是 DNS 解析出了问题。你可以在 Quantumult 的“设置”中，找到“DNS”选项，尝试将其设置为 1.1.1.1 或 8.8.8.8 等公共 DNS。

问题二：连接时提示“配置错误”？

这大概率是你的参数格式写错了。请仔细对照我们上面提供的语法模板，检查是否有多余的空格、缺少逗号或拼写错误。特别是 username= 和 ws=true 这些参数，一个字符都不能错。

问题三：速度很慢，不稳定？

可以尝试更换传输协议。比如将 WebSocket 改为 gRPC 或 HTTP/2，有时候会有意想不到的提速效果。另外，检查一下你的服务器线路是否拥堵，或者尝试更换一个离你更近的节点。

FAQ

Hysteria2 与传统代理协议有何不同？
Hysteria2 使用基于 QUIC 的高性能传输协议，可显著降低延迟并提升抗干扰能力。它特别适合高丢包或高延迟网络环境，提供流畅的浏览和视频播放体验。
V2Ray QUIC 模式适合高丢包网络吗？
QUIC 基于 UDP 协议，支持多路复用和零握手，能在高丢包和不稳定网络中减少延迟和丢包。适合视频、游戏和即时通讯等高频应用场景，提高稳定性和速度。
Shadowrocket 的节点测速结果如何应用？
节点测速结果可用于策略组选择和自动切换，程序会根据延迟和丢包率选择最优节点。这样访问海外网站或流媒体时，可以保持高速和稳定的网络体验。
Sing-box 的策略组支持按延迟选择节点吗？
支持。Sing-box 会根据节点延迟自动选择最优节点，结合策略组和路由规则，实现智能分流。延迟最低的节点优先被使用，提高网络访问速度和稳定性。
Nekoray 如何实现节点订阅自动更新？
支持订阅 URL 自动更新节点，程序定期下载并替换旧节点。保证节点列表最新，减少手动维护，提高使用效率和便利性，同时保证网络访问稳定性。
Netch 的全局代理与规则代理有何不同？
全局代理将所有流量都通过节点转发，而规则代理只针对指定 IP、端口或应用。全局代理适合游戏和全局科学上网，规则代理适合优化带宽和分流特定流量。
Surfboard 的配置文件可以与 Clash 通用吗？
Surfboard 基于 Clash 核心，因此支持大部分 YAML 配置文件，但部分字段如 rule-provider、external-controller 等可能不兼容。建议使用订阅转换工具将 Clash 文件转换为 Surfboard 兼容格式导入。
Sing-box 如何按 IP 段实现智能分流？
Sing-box 支持根据 IP 段匹配流量，将国内流量直连、国外流量走代理。结合策略组和规则文件，实现精细化流量管理，保证访问速度和稳定性，同时提高节点使用效率。
Surfboard 与 Shadowrocket 有什么区别？
两者都是 iOS 上的代理工具。Shadowrocket 功能更全面、更新更频繁，而 Surfboard 以轻量和快速见长。若只需简单分流与节点切换，Surfboard 足以满足日常使用。
Surfboard 能否同步 Quantumult X 的规则？
Surfboard 的规则语法与 Quantumult X 相似，但并非完全兼容。部分策略组或脚本需手动修改格式方能正常使用，因此不建议直接复制，最好通过转换工具处理。
